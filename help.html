Getting started

A new diagram already holds a small process: a start, a task and an end, both the first time you open the editor and each time you click New. Build from there, or delete these shapes to draw something else.

  1. Pick a shape in the palette on the left, then click the canvas to place it.
  2. Click a shape: its context menu appears next to it and lets you append the next element, already connected.
  3. Double-click a shape to type its label.
  4. Name the file in the field on the left of the toolbar. That name is used when saving and for every export.

Your work is kept in the browser after every change, and you find it as you left it when you reopen the page. The "Autosave" label in the toolbar is there to remind you.

The FR or EN button switches the interface language. The Theme button next to it moves to the next theme on each click: automatic (your system's), light, then dark. Its tooltip shows the current theme. The help follows the same choice and has its own button, top right. The browser remembers both choices.

BPMN 2.0 is an international standard: published by the Object Management Group (OMG) and adopted by ISO as ISO/IEC 19510:2013, identical to BPMN 2.0.1. Its notation and execution semantics are the same for every tool and every team: a diagram made here reads the same elsewhere, and the .bpmn file opens in any compliant editor or engine.

Why BPMN rather than a flowchart?

General drawing tools such as draw.io, Lucidchart or Visio draw boxes and arrows. A shape means what its author meant, and every team invents its own conventions. BPMN gives each symbol a defined meaning:

  • Who does what: pools for organisations, lanes for roles, message flows for what they exchange.
  • What triggers and what waits: start, timer, message and error events, and events attached to a task for deadlines and exceptions.
  • How paths split and join: exclusive (a single branch), parallel (all of them) and inclusive (some of them) gateways, each with its own rule.
  • A file that tools understand: the .bpmn file describes the process itself, not its picture. It can be checked, simulated, turned into a report, read and written by an AI agent, and run by a workflow engine. A drawn flowchart allows none of this.
  • No lock-in: the same file opens in any compliant editor, today and in ten years.

Drawing

The palette

The palette on the left holds the selection tools (hand , lasso , space , connect ) and then the shapes: events, tasks, gateways, subprocesses, data objects, pools and lanes. The button at the bottom of the palette opens the full list of BPMN elements, with a search by name.

The context menu

When you select an element, a set of buttons appears next to it. They vary with its type. For a task, you will find:

  • First row: append an end event, a gateway, a task or an intermediate event. The new element is placed to the right, already linked by a flow.
  • Add text annotation (the dotted bracket) adds a comment linked to the element.
  • Append element (the three dots) opens the full list of elements that can follow, sorted by family (tasks, gateways, sub-processes, events, data), with a search field.
  • Connect to other element (the slanted arrow): click it, then click the target element to draw a flow.
  • Change element (the wrench) turns the element into another type without redrawing it: its links and label are kept. See the details below.
  • Delete (the bin) removes the element and its flows.
  • Set color (the brush) and Text formatting (the A button) open a small color menu for one element, or their full menu for several. They are covered in Colors and text.
  • Copy style (the eyedropper) remembers the element's fill, stroke, font and text color. Paste style (the roller), shown once a style has been copied, applies them to the selected element, or to several at once.

Change element

The wrench opens the Change element window. It lists the types that fit the selected element: a task can become a user task, a service task, a call activity or a sub-process, a start event can become a message or timer start event, and so on. Type a few letters in the search field to filter the list, then click a type or press Enter. The R key opens the same window from the keyboard.

For a task or a sub-process, the icons at the top right of the window add a marker without changing the type: parallel multi-instance , sequential multi-instance and loop . Click again to remove the marker. You then set the loop cardinality and completion condition in the Process panel.

Undo and redo

The Undo and Redo buttons, at the top left of the canvas, step through your edits and the co-pilot's one at a time, like Ctrl+Z and Ctrl+Y. They are greyed out when there is nothing to undo or redo.

Tidy up, and a layout or a diagram replaced by the co-pilot, reload the whole diagram. Just before, the editor keeps a copy: Undo goes back to it in one step, but older edits can no longer be undone one by one. Opening a file or creating a diagram starts with an empty history.

Task types

A small icon at the top left of the task says who or what performs it:

  • User: a person, in an application
  • Manual: a person, without an application
  • Service: a system, through an automated call
  • Script: a script run by the engine
  • Business rule: a decision, often a DMN table
  • Send: sends a message, then goes on
  • Receive: waits for a message

Markers

A marker at the bottom center of an activity says how it runs:

  • Loop: repeats while a condition requires it
  • Parallel multi-instance: one run per item of a list, at the same time
  • Sequential multi-instance: one run per item, one after the other
  • Compensation: undoes the work of an activity already completed
  • Ad hoc: activities in a free order

Event matrix

A single circle for a start, a double one for an intermediate event, a thick one for an end. A filled symbol throws, a hollow one catches. A dashed border marks a non-interrupting event: the activity or the process goes on. Colors and text

Colors

With several elements selected, the brush in the context menu offers 17 ready-made colors, each with a pale fill and a readable dark stroke. Custom color… accepts any shade. The stroke is then computed to keep good contrast, and a dark fill gets light text.

Text formatting

With several elements selected, the A button in the context menu formats their labels: bold, italic, underline, size (10 to 24), font (sans serif, serif, monospace, Verdana, Tahoma, Trebuchet, Georgia, Palatino, Comic) and color. The Auto color picks black or white, whichever reads better on the element's fill. Default text removes all formatting.

In the Process panel

For a single selected element, the brush and the A button of the context menu open a small menu: five shape or text colors, then, under Used in this diagram, up to three colors used elsewhere, the most recent first. Default removes the color, and More… opens the Process panel on its Shape or Text group, with more room. For several selected elements, they open the full menus described above.

  • Shape: two rows of ready-made colors, pale fills then vivid fills that also turn the text white, then a Fill and a Stroke to set one without the other (the square opens your system's color picker). The field next to the square shows the color's hexadecimal code, or in gray the default color's code when none is set: type one, for example #1E88E5, then Enter to apply it. A flow only has a stroke.
  • Text: bold, italic, underline, size and font (when nothing is set, each list shows the value applied, for example 12 and Arial, or 11 for labels placed under the shape, such as event labels), two rows of text colors as round dots (the first: black, a gray gradient and four dark shades for light fills; the second: white and vivid shades, three of them bright for dark fills), an Other row for any color, with its square and hexadecimal code as for the fill, then Auto and Default text.
  • Used in this diagram, in the Style group, lists on one row, most recent first, up to 8 styles set elsewhere (colors and text formatting together), by you or by the co-pilot. One click applies one of them to the selected element.
  • Copy style, in the Style group above the other two, remembers the element's fill, stroke, font and text color. Its button shows an eyedropper in a square painted with the selected element's colors: that is what will be copied. Paste style applies the copied style to another element. Its button gives a preview: a roller in a square, the square in the shape colors, the roller in the text color. To handle several elements at once, select them and use the Paste style roller of the context menu. The browser keeps this copy, even from one diagram to another.

Each change is undone with Ctrl+Z.

Colors and styles are saved in the .bpmn file following the standard, and other bpmn.io tools read them back. Underline does not show in the PDF export, which also replaces fonts with Helvetica or Times, depending on their family. A font missing from a computer is replaced by a similar one.

Check and tidy up

BPMN checks (bpmnlint)

The editor has a built-in BPMN checker, bpmnlint. It reviews your work as you draw, with its 27 recommended rules and one rule of BPMN Pilot's own: disconnected element, process with no start or end, badly connected gateway, element without a label, trigger not allowed on an event… A few rules apply the standard, most are modeling best practices: a diagram that breaks them is still valid BPMN, but it reads or runs less well. The Nature column of the table tells them apart. They are advice and never block saving.

  • A badge on the element flags an issue: red for an error, orange for a warning.
  • Hover the badge to read the message. The rule name follows in brackets, for example no-implicit-end.
  • Click that name to open the rule's explanation, with a wrong and a right example.
  • The counter at the bottom left of the canvas shows the number of errors and warnings. Click it to hide or show the badges.

Saving and My diagrams

Autosave (localStorage)

The editor keeps your work in the browser one second after each change, and shows the time of the last save next to "Autosave". This autosave has a single slot: clicking New or opening a file replaces its content.

My diagrams

To keep several processes, open My diagrams. Give your work a name and click Save. The list then lets you reopen, rename or delete each entry. Ctrl+S updates the one that is open, and Save as new makes a copy.

This list is stored in this browser, on this device. It is not synced, and it is lost if you clear the site's data or browse in private mode. To keep a process for good, or share it, export it as a .bpmn file.

The Save to choice sets where your work goes: This browser or Server. An entry saved on the server opens from any browser that reaches it, and it is also kept as a .bpmn file (see Your files in the Docker version).

An entry saved in This browser stays on this device. It is not synced, and it is lost if you clear the site's data or browse in private mode. Choose Server to find it elsewhere, or export a .bpmn file to share it.

Multi-level map (call activity)

An end-to-end process rarely fits on one screen. Keep an overview of a few steps, and detail each one in its own diagram: a call activity points to the diagram that describes it, and one click goes down to it.

  1. Turn the task into a call activity: Change element (the wrench), then Call activity. It keeps its links and label, and gets a thick outline. The Sub-level group appears in the Process panel.
  2. + Create the diagram of this level saves in My diagrams a diagram named after the activity, with a start and an end, and links it. You can also pick a diagram already saved from the list.
  3. The Open marker, at the bottom of the activity, or Open this level in the panel, opens the linked diagram. The breadcrumb trail, at the top of the canvas, shows the path taken: ↑ Up, or a click on a level, goes back to it, with the starting activity selected.

Before each change of level, the open diagram is saved in My diagrams (updated, or created under its name if it was not there): nothing is lost. Opening another diagram, a file or New leaves the map and clears the trail. A call activity without a link has a dashed + Link marker, and a link whose diagram is gone from My diagrams, a red one.

The link is kept in the .bpmn file: the name of the linked diagram (bpmnpilot:linkedDiagramName), which finds it in another browser where it is saved under that name, and the id of the called process in the standard calledElement attribute, which execution engines read. In Presentation mode, the markers of linked activities and the trail stay: you go down and back up in front of the audience. Procedure sheets and the documentation page give, for each linked activity, the diagram that details it.

My diagrams lives in this browser: to pass a map on, export each level as a .bpmn file, under the name of its diagram.
A diagram created from a level saved on the server is stored on the server too: the whole map opens from every browser that reaches the server.

Open, import, export (XML, SVG, PNG, PDF)

Open

  • Open, then .bpmn, .xml or encrypted file…, opens a file from your disk.
  • Paste XML… opens a diagram copied as code, for example from another tool or an AI answer.
  • From a table… builds a process from a table of steps, without AI (see below).
  • Roles × tasks grid… builds a process in a workshop, one task per row and one role per column (see below).
  • You can also drop a .bpmn file onto the page.
  • Compare with a file… shows the differences between a file from your disk and the open diagram, without changing anything (see below).

The editor reads BPMN 2.0 files from other tools (Camunda, Bizagi, Signavio…). If a file has no layout, the editor computes one on opening. The other way round, a file saved here opens in other BPMN 2.0 editors, Camunda Modeler included, to complete it or run it in an engine. What is specific to BPMN Pilot (probabilities, goals, AI agent steps, user stories, sub-levels, co-pilot analysis) is ignored there without error, and Camunda Modeler and the other editors built on bpmn.io keep it when they save the file again. An encrypted file (.bpmn.enc) opens the same way, after its password.

Create from a table (no AI)

Model an AI agent (ad-hoc sub-process)

When a step of the process is handed to an AI agent (an LLM, an assistant, a bot that decides its own actions), BPMN 2.0 already has the right shape: the ad-hoc sub-process. Its inner activities are not connected by flows: whoever runs it picks which ones to start, and in which order. For an agent, these are its tools. The file stays standard BPMN, readable by any tool.

Mark an AI agent step

  1. Select a task or a sub-process. In the Process panel, AI agent group, tick AI agent step. A task or a plain sub-process becomes an ad-hoc sub-process. An AI agent badge marks it on the canvas.
  2. Expand it and place inside one task per tool of the agent, with no flows between them and no start or end event: for example a service task "Look up the customer file".
  3. Describe in the Documentation field what the agent decides alone and what it must not do.

Human review and exit

A safe agent step has two safeguards drawn in the process: a person reviews its result before it is used, and a path exists if the agent fails or takes too long. The checks flag a missing one (rules bpmnpilot/agent-review and bpmnpilot/agent-escalation, as warnings), and the process report turns it into an improvement area.

Under the box, the panel says what is missing. Complete the pattern adds it in one go: a user task "Review the agent's proposal" right after the step (what follows moves to the right), and a "Time limit exceeded" timer on its boundary, leading to "Handle it manually". Then rename and adjust these elements to your case. Ctrl+Z undoes it all.

The AI co-pilot and MCP agents can draw this pattern: ask them to add an AI agent step, or see the prompt example. The mark is saved as the bpmnpilot:agent attribute, which other BPMN tools ignore: they read a plain ad-hoc sub-process.

Review, checks and traceability

Around each answer, the co-pilot shows what it understood, what the editor checked and where the result comes from.

  • Review of the request. Before drawing a description (200 characters or more, or an attached file), the model lists what is ambiguous or missing: actors, trigger, results, decisions, exceptions and deadlines, loops, documents exchanged, vague wording. Each point has a severity (Blocking, Important, Minor), the question to settle and, when there is one, the passage quoted. The drawing starts right away, with assumptions the model lists at the end of its answer. Answer the questions in your next message to refine the diagram.
  • Check report. After each answer that changed the diagram, the editor checks it itself, without calling the model. The report gives the counts (pools, lanes, activities, gateways, events, flows) and six checks: well-formed XML, conformance to the BPMN 2.0 metamodel (known elements and attributes), references and scopes (a sequence flow stays in its process, a message flow connects two pools), every element drawn (complete DI), reimport by bpmn-js without warnings, no bpmnlint error. Click the report line to unfold the details.
  • Automatic correction. When a check fails, the problems go back to the model, which fixes them on its own, two rounds at most. A correction that does not reduce the number of problems is undone. The report says so, for example "1 correction requested, 1 kept".
  • Traceability. Under each answer: provider, model, duration, date and time, and the source (message length, names of the attached files). Retry from the same source, on the last answer, puts the diagram back as it was before that answer and sends the same request again to the model chosen at that time, for example to compare two models.
  • Destination. A line above the input says where the message goes, to which provider and model: from your browser in the online version, through your server in the Docker version. A provider on your network, such as Ollama, is shown as such. The message, the attached files and the current diagram are sent with each message.

The review and the automatic correction send extra requests to the model: they take time and are billed like the others. The Review the request and correct automatically box, in Options, turns both off. The report, the traceability and the destination line stay.

Expert mode

Tools to test a model and prepare its execution: token simulation, heatmap, process report, event log analysis, AI potential, risks and compliance, Camunda export, DMN decision tables. None of this is needed to draw. The Expert button of the toolbar turns them on, and Choose modules… turns on only the ones you use.

Turn on Expert mode

These features are for testing a model and reporting on it: replaying the process, measuring how instances spread, producing a report, comparing it with the logs of your software, and linking the decisions of the process to DMN tables.

The Expert button of the toolbar opens a menu, with the commands of the modules that are on: Simulation, Process report (PDF), Process report (Markdown), Process report (Word), Analyze an event log, Propose probabilities, Co-pilot analysis, AI potential by activity and User stories by activity, the last four greyed out until a model is chosen for the co-pilot: a small help icon says so on hover. Choosing an entry turns expert mode on: the button turns blue, and the Probability (%) field appears in the Process panel. The mode stays on until Leave expert mode, at the bottom of the same menu, and the browser remembers it. This entry is hidden while a simulation runs. Outside this mode, the editor shows none of these tools. The co-pilot checks and the MCP drawing tools are available either way.

Choose modules

Choose modules…, at the bottom of the menu, opens a window with one switch per function: Token simulation, Heatmap, Process report, Event log analysis (process mining), AI potential, Risks and compliance, User stories, Camunda export and Decision tables (DMN). Turn on only what you use: the Expert menu and the Process panel only show the commands of the modules that are on. The heatmap needs the simulation. By default, the simulation, the heatmap, the report, the event log analysis, the AI potential, the risks and the user stories are on, and the Camunda export and decision tables are off. The browser remembers your choices.

Turning a module off leaves the diagram as it is: the probabilities, decisions, AI potential, risks, user stories and process identity already set stay in the file. The Decision tables (DMN) module, once on, adds the markers of business rule tasks, the Decision (DMN) group of the Process panel and the Decisions of the diagram… entry: see Decision tables (DMN). Simulation and heatmap

Expert, then Simulation, switches to simulation mode: a play button appears on each start event. Click it to send a token, and watch it follow the flows. At exclusive gateways, you choose the path. A slider at the bottom of the canvas sets the token speed, from 0.25× to 4×. A log lists the steps taken, so you can check that the process ends in every case. The Expert menu then offers only Stop simulation, and an orange dot on the button shows that a simulation is running. Stopping goes back to editing and keeps expert mode on: the canvas is locked during the simulation, and the branch probabilities are set once it has stopped.

The checkbox marked with a Christmas tree, at the end of the speed box, spins the Leylines gradient around the outline of each step a token enters. It is off by default, and the browser remembers your choice.

Branch probabilities

The Probability (%) field, in the Simulation group of the Process panel, appears in expert mode for a sequence flow leaving an exclusive, inclusive, complex or event-based gateway. It takes a value from 0 to 100 and can be undone like any change.

When a model is chosen for the co-pilot, Propose probabilities, in the Expert menu, asks it for realistic values from the labels, conditions and documentation. Its values are marked like its other changes, and undone in one click. Under the field, "Proposed by the AI co-pilot, to review" stays until you change the value or tick Keep the co-pilot's value. Until then, the process report lists the gateway as to complete.

  • Exclusive, complex or event-based gateway: a single flow is taken. Flows without a value share equally what remains up to 100%, then the whole set is scaled to a total of 100%.
  • Inclusive gateway: each flow is taken according to its own probability, and at least one always is. The join waits for as many tokens as the split sent.
  • Parallel gateway and uncontrolled flows: every flow is taken, and the field does not appear.

The value is saved in the .bpmn file as the bpmnpilot:probability attribute (namespace https://bpmn.leylines.fr/schema/bpmn-pilot/1.0), which other BPMN tools ignore without error. The co-pilot and MCP agents set it with the update_elements tool.

Process goals

A figure goal is set on the element it measures, in the Simulation group of the Process panel, in expert mode:

  • on an end event, the share of instances that should end there, for example at least 80 % of requests accepted;
  • on an activity, the number of passes per 100 instances, each rework counting as one more pass, for example at most 15 requests for documents per 100 files.

Goal is says whether it is a minimum or a maximum. After Run N tokens, the process report compares each goal with the result: reached, not reached (a warning and an improvement area), or not measured until a run has taken place. The AI co-pilot reads the goals in the report and cites them in its analysis, without changing them: they remain your choices. They are saved as the bpmnpilot:goalShare and bpmnpilot:goalOp attributes, which other tools ignore.

Heatmap

The heatmap shows where the instances of a process go. It colors each element and each sequence flow by the number of tokens that went through it, from pale blue to red. Without reading the model element by element, you see the paths never taken, the activities almost every instance goes through, and the rework loops that run the same activity several times. Use it to validate a model before sharing it, and to find where a process repeats or concentrates before discussing a redesign.

  1. Start the simulation (Expert, then Simulation). The speed box, at the bottom of the canvas, holds two controls: Heatmap, and Run followed by a field that sets the number of tokens, from 1 to 10,000 (100 by default).
  2. Check coverage. Turn on Heatmap, then send a few tokens, picking a different path at each gateway. The map follows every step. Anything left dashed grey was never reached: a forgotten branch, an unreachable end event.
  3. Measure the distribution. Outside the simulation, select each flow leaving an exclusive, inclusive or event-based gateway, and fill in the Probability (%) field of the Simulation group, in the Process panel. Flows without a value share the rest equally. Then start the simulation, enter the number of tokens and click Run (or press Enter in the field): the result is immediate, with no animation.
  4. Read the map. A badge gives the number of passes on each activity and event, with the share of instances ("31 · 31 %"). Above one pass per instance, it gives the average number of executions ("131 · 1.3×"): that is a rework loop. Flow width follows the same count.

With decision tables on, an exclusive gateway right after a business rule task linked to a table splits computed tokens by that table: each rule weighs the same, and each outgoing flow gets the rules whose output it names, by its name ("high") or its condition (risk = "high"). The default flow gets the others. As soon as one flow of the gateway has a probability, the probabilities win.

The heatmap counts passes: it measures neither durations nor costs. This run follows gateways according to their probabilities, and does not trigger boundary events. The map disappears when the simulation stops, but its counts remain available as long as the diagram does not change: the PDF process report includes it on a page of its own. Probabilities are saved in the .bpmn file, under an attribute of BPMN Pilot that other tools ignore.

Process report

The process report turns the diagram into a document anyone can read without a BPMN tool: a sheet to hand to a team, attach to a quality procedure or present to the process owner. It also works as a modeling review: it lists errors, warnings and missing information, and derives improvement areas by priority.

Expert, then Process report (PDF) or Process report (Markdown). The report is built from the diagram, with no extra input:

  • key figures and the diagram, with each element concerned by a finding outlined in the color of its level;
  • modeling findings, in three levels: Error in red (bpmnlint rule broken, unreachable element, instance that cannot complete), Warning in orange (departure from good practice, frequent rework), To complete in yellow (no documentation, unlabeled conditions, lane with a single activity). Their source is given: bpmnlint, model check or simulation;
  • improvement areas, by priority, with the expected effect;
  • the process goals, reached or not according to the last run of tokens;
  • the AI co-pilot's analysis, if one was made (see below);
  • after a simulation, the heatmap and its figures: most traversed activities, passes and observed share of each gateway branch, elements never reached;
  • the six quality checks, computed in the editor, without AI;
  • the DMN decision tables, with the tasks that call them and their findings;
  • end events, activities by lane, and the element sequence: type, lane, documentation and outgoing flows with their conditions.

For a complete report, name each gateway with its question and each outgoing flow with its answer, place activities in lanes, and fill in the Documentation field of activities. None of this is required: the report flags what is missing. After a simulation, it adds the heatmap (in PDF), the number of instances per element, the share of each end event and rework.

Co-pilot analysis, in the same menu, asks the co-pilot for a reading of the process: it computes 100 tokens, reads the report, then saves a summary and its points (bottlenecks, rare paths, risks, improvements), each tied to the elements concerned. The analysis is kept in the .bpmn file, where other BPMN tools ignore it: it follows the diagram and is paid for only once. The report presents it as written by the co-pilot, with the model and the date, to be validated by the process owner. If the diagram changes afterwards, the report says so. Ctrl+Z undoes it. Both entries stay greyed out until a model is chosen, and each costs one chat turn. An MCP agent does the same with the set_report_commentary tool.

The report also comes as a Word document, with Process report (Word), to rework and put in your organization's style. It grows with what you fill in: the process identity at the top, the RACI matrix when activities have a RACI, the AI potential, the risks and controls and the compliance matrix when they are filled in.

Analyze an event log (process mining)

A diagram says how the process should run. The software that supports it (ERP, CRM, ticketing tool) keeps a record of what actually happened: for each case, which step, at what time. That record is an event log. Expert, then Analyze an event log (process mining), compares it with the open diagram.

  1. The file. A CSV table (one row per step carried out) or an XES file (IEEE 1849), optionally compressed as .xes.gz. Try with the example loads a fictitious log of 412 orders and the matching diagram.
  2. The columns. The editor guesses which column holds the case (order, request, ticket), the step, the start time, the end time and the resource. Only the first three are required. Correct them if needed; the preview updates. ISO dates, day/month/year, month/day/year and Unix timestamps are recognized.
  3. The steps. Each step of the log is matched with an element of the diagram by its name, even when misspelled. A step left on Not in the diagram counts as a deviation.

Analyze opens a panel on the canvas with three tabs:

  • Passes: how many cases went through each element and each flow, colored like the heatmap but with the real figures. An element never reached turns dashed grey. Apply the log percentages to the gateways writes the observed shares into the Probability (%) field of the branches, marked "Observed in the event log": the simulation and the report then run on real figures. Ctrl+Z undoes it all at once.
  • Durations: the median wait before each step, and its duration when the log gives a start and an end. The three longest waits are flagged as bottlenecks.
  • Deviations: the share of cases that follow the diagram and a conformance measure (fitness, from 0 to 1), then the deviations from most to least frequent: skipped step, steps out of order, step not in the model, case stopped midway. Clicking a deviation selects the element.

Without a starting diagram, Draw the process from the log… derives a first version: the steps and how they follow each other, with two sliders to hide rare steps and paths. This calculation runs without AI and only produces exclusive gateways. Ask the AI co-pilot sends it the same totals so it draws a finer model, with parallel branches.

The log stays in the browser. It is neither saved nor sent, and case or resource names never leave the editor. The process report gains a "What actually happens" section. The Keep the totals in the .bpmn file box, unchecked by default, stores only the totals (passes, durations, deviations) in the diagram, to find them again next time. By contrast, a CSV file attached in the co-pilot conversation goes to the AI provider in full: to keep the data on your computer, use the Expert menu.

This function needs the Event log analysis (process mining) module, on by default, in Expert then Choose modules….

Table checks

The editor reads each table, without AI, and flags:

  • a table with no input, no output or no rule, a decision with no logic;
  • text without quotes, which FEEL would read as a variable name;
  • an output that gives a value outside its allowed values;
  • two rules that can both apply under the Unique hit policy, or with different outputs under Any;
  • an allowed value of a text input that no rule covers;
  • a business rule task with no decision, or linked to a decision missing from the diagram.

Overlaps are computed on numbers (comparisons, ranges), quoted text and booleans. A more complex FEEL expression is not compared. The findings show in the Decision (DMN) group, in the process report, section Decisions (DMN), and in the result of validate_diagram.

  • If you use the AI co-pilot, your messages, the diagram, your attached files and your key go straight from your browser to the chosen provider, which applies its own terms and privacy policy. Do not include data you would not trust that provider with.
  • The co-pilot's voice dictation recognizes speech on your device: neither the sound nor the dictated text leaves the browser until you send the message.
  • Like any web host, GitHub Pages keeps technical logs, including your IP address.
  • The stable site counts its visits anonymously, without cookies (nothing is counted on the development version), according to the recommendations of the CNIL (the French data protection authority, page in French) for audience measurement exempt from consent. The IP address is not recorded. It is only used to determine the country, region and city. The data collected is: the page viewed and the referring site, the device characteristics sent by the browser, and a few actions without their content (creating, opening or exporting a diagram, using the co-pilot, type of provider connected, active time in ranges, click on the support link). "Do Not Track" and "Global Privacy Control" signals turn the measurement off.
  • The site loads no third-party script.

    You are using the Docker version of the editor, installed on your machine or network. Compared with the online version, it adds:

    • API keys stored on your server, which never reach the browser,

    The MCP server gives the agent modeling rules (naming, gateways, happy path) along with its tools, and five ready-made prompts. Depending on the agent, they appear in a prompt menu (the + button in Claude Desktop) or as commands (/mcp__bpmn-pilot__review_diagram in Claude Code):

    • model_process: draws a process from your description,
    • model_collaboration: draws one pool per organization, with the messages between them,
    • review_diagram: lists what to improve in the open diagram, without changing anything,
    • tidy_diagram: renames to the conventions, fixes the errors and tidies up, keeping the meaning,
    • critique_description: lists what is ambiguous or missing in a description, with severity, quoted passage and question, before drawing,
    • add_agent_step: adds an AI agent step with its tools, its human review and its exit,
    • write_user_stories: writes the user stories and acceptance criteria of each activity.

    Without an open browser (headless mode)

    By default, the agent draws in an editor tab, which must stay open. The optional headless mode lifts this condition: an agent draws, checks, exports and reads the report with no tab open, for example to model in one run the processes of your documentation.

    • It is turned on by installing the docker-compose.headless.yml file instead of docker-compose.image.yml (see the repository README). It adds a renderer service: a headless Chromium, isolated on an internal network, with no access to the internet or to the API keys.
    • When an agent calls a tool and no tab is open, the server opens the editor in an invisible tab of that browser. The tools work there exactly the same, images and PDF included. The tab closes after 5 minutes without a call.
    • Each diagram drawn this way is saved in My diagrams, on the server, under a name such as "Agent 2026-11-28 14h05".
    • If you open the editor while the agent is working, a banner says so at the top of the canvas. Open loads the diagram in your tab, and the agent's next calls arrive there. Without this click, the agent goes on in its invisible tab: it never switches by itself to the diagram in front of you.
    • With the returnFile option, export_diagram returns the file to the agent (PNG, SVG, PDF or BPMN), which can use it directly, with or without an open tab.

    Your files in the Docker version

    The server keeps everything in a bpmn-data folder, next to its compose file (or in the folder set by BPMN_DATA_DIR). Open it with your file explorer to get your work back:

    • diagrams: what My diagrams saves on the server, one .bpmn file per diagram, named after it. Renaming an entry renames its file. Leave .index.json in place: this hidden file links the folder to the editor. A .bpmn copied into this folder appears in the list, under its name.
    • exports: the exports made with the Server or Both destination. An export never replaces a file: a second Order process.pdf becomes Order process (2).pdf.

    Install on your device (PWA)

    BPMN-Pilot is a PWA (Progressive Web App): thanks to its web app manifest, the browser installs it in its own window, without the address bar, launched from the Start menu, the Dock or the home screen.

    • Chrome and Edge (computer and Android): the Install button in the toolbar, which appears only when the browser offers installation, or the install icon at the right of the address bar.
    • Safari on a Mac: File menu, Add to Dock.
    • iPhone and iPad: Share button, Add to Home Screen.
    • Firefox on a computer does not support installing PWAs.

    Offline (service worker)

    After a first visit, the editor, this guide and the showcase page open without a connection, installed or not: a service worker caches the site's files (Cache API). The GIFs of this guide are cached once displayed. The AI co-pilot needs a connection to reach its provider's API: offline, it says so.

    When a new version is published, its service worker waits: a banner above the canvas offers to Reload. Nothing reloads on its own, and reloading keeps the diagram in progress.

    On iPhone and iPad, the installed PWA has its own storage (localStorage and IndexedDB), separate from Safari: the diagrams of My diagrams in Safari do not appear in it. To move a diagram from one to the other, export it as a .bpmn file and open it on the other side.

    Docker version: the PWA installs on localhost or over HTTPS (the secure context browsers require). Without a service worker, it does not work offline: the AI co-pilot, the MCP server and saved diagrams go through the server.

    On a phone or tablet

    The editor is designed for a computer screen, a mouse and a keyboard. On a phone, it is mostly for viewing a diagram.

    • What works: opening a .bpmn file or an entry from My diagrams, panning and zooming with your fingers, exporting.
    • What is difficult: placing and connecting shapes, typing labels, using the Process panel and the co-pilot, for lack of room.

    Below 900 pixels wide (or 500 high), a banner above the canvas says so. Close it with its cross: it does not come back in this browser. On a small screen the Process panel also starts hidden. On a tablet, the button on the right of the toolbar opens it. On a phone, the toolbar is wider than the screen and its last buttons are out of reach.

    To model, use a screen at least 1280 pixels wide, or a tablet in landscape with a keyboard and a mouse.

    FAQ

    Do I need an account?

    No. The editor works without an account. Only the AI co-pilot needs an API key from an AI provider.

    No. The editor works without an account. Only the AI co-pilot needs an API key, set on the server or entered in Options.

    Can I use the editor without AI?

    Yes. The whole editor works without an API key: drawing, checks, simulation, saving and exports.

    My diagrams are gone. What happened?

    They are stored in one browser, on one device. So they do not show anywhere else, in private mode, or after the site's data is cleared. Export what you want to keep as .bpmn.

    Those saved in This browser only show there: not in another browser, in private mode, or after the site's data is cleared. Those saved on the Server stay available from any browser. Export what you want to keep elsewhere as .bpmn.

    "Test" fails with OpenAI.

    OpenAI sometimes refuses calls made directly from a web page. Use Anthropic, Mistral, xAI or Ollama on this site, or install the Docker version, which goes through its own server.

    My MCP agent does not draw.

    The agent draws in the last editor tab you used: keep it open, or switch to the headless mode. The MCP badge in the toolbar should read "MCP: ready": the tab is linked to the server and waits for an agent. As soon as an agent connects, it shows its name instead, for example "MCP: Claude Code", and hovering it gives its version and the time of its last call. After 15 minutes without activity from the agent, the badge goes back to "MCP: ready", and hovering it still shows the last agent's name. The MCP protocol only sends this name and version: neither the model in use nor the account. Click it to get the address and the settings to paste into the agent again.

    If the agent gets a 401 error "MCP is closed", the editor is served under a name other than localhost without a token, so the server closes MCP access. Generate a token in the Connect an agent window, add it to the server variables (MCP_TOKEN), restart, then paste the new setting into the agent.

    An export to the server, or a save in My diagrams, fails.

    The server cannot write to its data folder: the error message names the folder. The data-init service of the compose file prepares this folder at each start. If the error stays, the folder belongs to another user than the server's (1000 by default, or PUID and PGID): the log docker compose logs mcp says so.

    How do I check what my model can do?

    The command docker compose exec mcp node mcp/check-providers.js tries each model set on the server: reply, tool call, image, PDF. It tells a setting error (key, address, model name) from a limit of the model, and costs a few hundred tokens per model.

    The co-pilot drew something unexpected.

    The pill's Undo button reverts the whole answer at once, Ctrl+Z one change at a time. You can also ask it for the fix in a few words. The more precise the description (roles, decisions, error cases), the better the result. A stronger model also helps with large processes.

    Can I open my files in another BPMN tool?

    Yes. The .bpmn file follows the BPMN 2.0 standard and opens in Camunda Modeler, Bizagi, Signavio and other compatible tools.

    Does it work on a phone or tablet?

    For viewing a diagram, yes. For modeling, not really: the editor is made for a computer screen, a mouse and a keyboard. See On a phone or tablet.
