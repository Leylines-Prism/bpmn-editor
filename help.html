Getting started

A new diagram already holds a small process: a start, a task and an end, both the first time you open the editor and each time you click New. Build from there, or delete these shapes to draw something else.

  1. Pick a shape in the palette on the left, then click the canvas to place it.
  2. Click a shape: its context menu appears next to it and lets you append the next element, already connected.
  3. Double-click a shape to type its label.
  4. Name the file in the field on the left of the toolbar. That name is used when saving and for every export.

Your work is kept in the browser after every change, and you find it as you left it when you reopen the page. The "Autosave" label in the toolbar is there to remind you.

The FR or EN button switches the interface language. The Theme button next to it moves to the next theme on each click: automatic (your system's), light, then dark. Its tooltip shows the current theme. The help follows the same choice and has its own button, top right. The browser remembers both choices.

BPMN 2.0 is an international standard: published by the Object Management Group (OMG) and adopted by ISO as ISO/IEC 19510:2013, identical to BPMN 2.0.1. Its notation and execution semantics are the same for every tool and every team: a diagram made here reads the same elsewhere, and the .bpmn file opens in any compliant editor or engine.

Why BPMN rather than a flowchart?

General drawing tools such as draw.io, Lucidchart or Visio draw boxes and arrows. A shape means what its author meant, and every team invents its own conventions. BPMN gives each symbol a defined meaning:

  • Who does what: pools for organisations, lanes for roles, message flows for what they exchange.
  • What triggers and what waits: start, timer, message and error events, and events attached to a task for deadlines and exceptions.
  • How paths split and join: exclusive (a single branch), parallel (all of them) and inclusive (some of them) gateways, each with its own rule.
  • A file that tools understand: the .bpmn file describes the process itself, not its picture. It can be checked, simulated, turned into a report, read and written by an AI agent, and run by a workflow engine. A drawn flowchart allows none of this.
  • No lock-in: the same file opens in any compliant editor, today and in ten years.
There is no account. Your diagrams stay in your browser. If you use the co-pilot, only the AI provider receives them. Neither this site nor its host has access to them. The site only measures its audience, without cookies (see Privacy).

Drawing

The palette

The palette on the left holds the selection tools (hand , lasso , space , connect ) and then the shapes: events, tasks, gateways, subprocesses, data objects, pools and lanes. The button at the bottom of the palette opens the full list of BPMN elements, with a search by name.

The context menu

When you select an element, a set of buttons appears next to it. They vary with its type. For a task, you will find:

  • First row: append an end event, a gateway, a task or an intermediate event. The new element is placed to the right, already linked by a flow.
  • Add text annotation (the dotted bracket) adds a comment linked to the element.
  • Append element (the three dots) opens the full list of elements that can follow, sorted by family (tasks, gateways, sub-processes, events, data), with a search field.
  • Connect to other element (the slanted arrow): click it, then click the target element to draw a flow.
  • Change element (the wrench) turns the element into another type without redrawing it: its links and label are kept. See the details below.
  • Delete (the bin) removes the element and its flows.
  • Set color (the brush) and Text formatting (the A button) open a small color menu for one element, or their full menu for several. They are covered in Colors and text.
  • Copy style (the eyedropper) remembers the element's fill, stroke, font and text color. Paste style (the roller), shown once a style has been copied, applies them to the selected element, or to several at once.

Change element

The wrench opens the Change element window. It lists the types that fit the selected element: a task can become a user task, a service task, a call activity or a sub-process, a start event can become a message or timer start event, and so on. Type a few letters in the search field to filter the list, then click a type or press Enter. The R key opens the same window from the keyboard.

For a task or a sub-process, the icons at the top right of the window add a marker without changing the type: parallel multi-instance , sequential multi-instance and loop . Click again to remove the marker. You then set the loop cardinality and completion condition in the Process panel.

Undo and redo

The Undo and Redo buttons, at the top left of the canvas, step through your edits and the co-pilot's one at a time, like Ctrl+Z and Ctrl+Y. They are greyed out when there is nothing to undo or redo.

Tidy up, and a layout or a diagram replaced by the co-pilot, reload the whole diagram. Just before, the editor keeps a copy: Undo goes back to it in one step, but older edits can no longer be undone one by one. Opening a file or creating a diagram starts with an empty history.

The minimap

It shows a small view of the whole diagram, top right of the canvas. It is collapsed when the editor opens: click Open minimap to expand it, then Close minimap to collapse it.

  • The orange frame is the part visible on screen. Drag it to move around.
  • Click anywhere else in the minimap to center the view on that point.
  • Ctrl+wheel over the minimap zooms the canvas.

On the canvas, the grid helps you line shapes up, and they snap to it.

Presentation

The Presentation button in the toolbar shows the diagram alone, full screen: no palette, panels or grid. Drag to move around, zoom with Ctrl+wheel, by pinching or with + and −. 0 fits the diagram to the screen, and 1 to 4 set the pointer effects. A click on an element shows its documentation sheet, and D turns the sheets on or off. The diagram cannot be edited in this mode. In expert mode, the Simulation button in the bar runs the token simulation there, with its controls: start, gateway choices, pause, log and speed. Esc or the cross returns to the editor, with the previous view.

The Pointer button in the presentation bar opens four switches, which can be combined freely. Each has its own key, which turns it on or off without opening the menu, and a short message shows its state.

KeyEffect
1Laser pointer: a red-orange dot with a short trail replaces the arrow on the diagram
2Highlight on hover: the hovered element and its flows light up, the rest of the diagram fades
3Ripple on click: a circle widens where you click
4Hide when still: after two seconds without moving, the cursor and the bar fade out, and come back on the first movement

The choices are kept in this browser. On a touch screen, the laser and the ripple follow the finger. The highlight relies on hovering and does not apply there.

Process panel

The right-hand panel shows the properties of the selected element. When nothing is selected, it shows those of the process, or of the collaboration if the diagram has pools. Its header gives the element type (User task, Message start event…) and its label.

Show and hide the panel

  • The button at the far right of the toolbar hides the panel. Click it again to bring the panel back. The canvas takes the freed space, and the browser remembers your choice for next time. This button has no keyboard shortcut.
  • To change the width, drag the handle on the left edge of the panel. With the keyboard, reach it with Tab and use the left and right arrows. Double-click it to go back to the default width.

Name, ID and Executable

Every element has the General group.

  • Name is the label shown on the canvas. Changing it here is the same as double-clicking the shape.
  • ID is the technical reference of the element in the XML file. Hidden on screen, it lets the file link elements together (a flow to its task, a pool to its process) and lets execution engines identify a step. It must be unique in the diagram and contain no spaces. The panel shows a message under the field when a value is refused. The editor assigns one automatically, so you only need to change it if an external tool expects a specific value.
  • Executable only applies to the process. When checked, it states (the isExecutable attribute) that a workflow engine such as Camunda or Flowable can deploy and run this process. For a diagram meant for documentation or analysis, you can leave it unchecked.

For a pool, the General group holds its name and ID, then those of the process it contains, with the Executable box. So once a diagram has pools, this is where the process settings live.

Responsibilities, systems and conditions (RACI)

The lane says which department performs an activity. The panel adds the rest, for each activity:

  • Assigned to, in the General group: the person or precise role who performs it (the R of RACI), in addition to the lane.
  • Systems used: the applications or tools, comma-separated (ERP, email, business tool…).
  • The Responsibilities (RACI) group: Accountable (A), who answers for the result; Consulted (C) and Informed (I), comma-separated.

These fields feed the procedure sheets, the process report (RACI matrix) and the RACI matrix (Excel) export, where R comes from Assigned to, or else from the lane. The AI co-pilot and MCP agents read and fill them too.

On a flow leaving an exclusive or inclusive gateway, the Condition field takes the rule in plain words, for example "Amount < 3000". It is stored in the standard conditionExpression element, which other tools read, and the export for Camunda translates it into the engine's language. While the flow has no other label, the condition shows on the diagram. The default flow has no condition.

Everything you enter in the panel is saved in the .bpmn file and carried over to XML exports.

Documenting elements

Every element has a Documentation field, saved in the .bpmn file. The editor turns it into a proper sheet: Markdown editing, templates per element type, dictation, drafting by the AI co-pilot, markers on the canvas, search, sheets in presentation mode and export as procedure sheets.

The documentation window

It opens from the Open pop-up editor button of the Documentation field, in the Process panel, or with a click on the blue marker of the element (see below). The text is saved as you type, and Ctrl+Z undoes it like any change.

  • At the top, three views: Write, Side by side (editing on the left, formatted preview on the right) and Preview. The browser remembers the last one.
  • The formatting bar adds bold, italic, heading, bulleted list, numbered list and link. Ctrl+B, Ctrl+I and Ctrl+K do the same from the keyboard.
  • Template ▾ inserts the headings of a template, the one for the element type first: purpose, actors, inputs, outputs, rules and references for an activity; question asked and criterion of each branch for a gateway, with one line per branch under its name; trigger, time limit or result for an event; purpose, scope, owner and indicators for the process.
  • Dictate types what you say at the cursor, with the co-pilot's on-device speech recognition: neither the audio nor the text leaves the browser. The button only appears in browsers that allow it.
  • Write with the co-pilot asks the AI co-pilot for a first version, based on the diagram (lane, neighbouring elements, conditions, documentation of the other elements) and your conversation. It writes "to be confirmed" where it does not know, keeps the text already there, and its text shows up in the window at once for review. The button stays greyed out until a model is set.

Spotting and finding documentation

  • A blue marker, top right, flags each documented element. On hover it shows a preview of the documentation; a click opens the window.
  • In Expert mode, a dotted marker also flags the activities without documentation, the ones the process report lists as "to complete". A click opens the window to write it.
  • Search, top left of the canvas, or Ctrl+F on the canvas, searches labels, ids and documentation. Under each result, the matching excerpt of the documentation. Enter centres the diagram on the element and selects it.

Using the documentation

  • In Presentation mode, a click on an element shows its sheet on the right of the screen. The Sheets button of the bar, or the D key, turns the sheets on or off. Esc closes the open sheet.
  • Export, then Procedure sheets (PDF) or Procedure sheets (Markdown) or Procedure sheets (Word), produces one sheet per activity in the order of the flow: its type, its lane, the assignee, systems and RACI when they are filled in, what comes before and after, then its formatted documentation. Documented gateways and events get a sheet too, and an activity without documentation is marked "to complete". The PDF starts with the documentation of the process and a clickable table of contents.
  • The process report shows the documentation on one line in its element sequence, and in full at the end of the Markdown report.
  • The AI co-pilot and MCP agents read the documentation of each element along with the diagram: ask them a question about the process, they use it to answer.

Colors and text

Colors

With several elements selected, the brush in the context menu offers 17 ready-made colors, each with a pale fill and a readable dark stroke. Custom color… accepts any shade. The stroke is then computed to keep good contrast, and a dark fill gets light text.

Text formatting

With several elements selected, the A button in the context menu formats their labels: bold, italic, underline, size (10 to 24), font (sans serif, serif, monospace, Verdana, Tahoma, Trebuchet, Georgia, Palatino, Comic) and color. The Auto color picks black or white, whichever reads better on the element's fill. Default text removes all formatting.

In the Process panel

For a single selected element, the brush and the A button of the context menu open a small menu: five shape or text colors, then, under Used in this diagram, up to three colors used elsewhere, the most recent first. Default removes the color, and More… opens the Process panel on its Shape or Text group, with more room. For several selected elements, they open the full menus described above.

  • Shape: two rows of ready-made colors, pale fills then vivid fills that also turn the text white, then a Fill and a Stroke to set one without the other (the square opens your system's color picker). The field next to the square shows the color's hexadecimal code, or in gray the default color's code when none is set: type one, for example #1E88E5, then Enter to apply it. A flow only has a stroke.
  • Text: bold, italic, underline, size and font (when nothing is set, each list shows the value applied, for example 12 and Arial, or 11 for labels placed under the shape, such as event labels), two rows of text colors as round dots (the first: black, a gray gradient and four dark shades for light fills; the second: white and vivid shades, three of them bright for dark fills), an Other row for any color, with its square and hexadecimal code as for the fill, then Auto and Default text.
  • Used in this diagram, in the Style group, lists on one row, most recent first, up to 8 styles set elsewhere (colors and text formatting together), by you or by the co-pilot. One click applies one of them to the selected element.
  • Copy style, in the Style group above the other two, remembers the element's fill, stroke, font and text color. Its button shows an eyedropper in a square painted with the selected element's colors: that is what will be copied. Paste style applies the copied style to another element. Its button gives a preview: a roller in a square, the square in the shape colors, the roller in the text color. To handle several elements at once, select them and use the Paste style roller of the context menu. The browser keeps this copy, even from one diagram to another.

Each change is undone with Ctrl+Z.

Colors and styles are saved in the .bpmn file following the standard, and other bpmn.io tools read them back. Underline does not show in the PDF export, which also replaces fonts with Helvetica or Times, depending on their family. A font missing from a computer is replaced by a similar one.

Check and tidy up

BPMN correctness checks

The editor has a built-in BPMN correctness checker, bpmnlint. It reviews your work as you draw, with its 27 recommended rules: disconnected element, process with no start or end, badly connected gateway, element without a label… They are advice and never block saving.

  • A badge on the element flags an issue: red for an error, orange for a warning.
  • Hover the badge to read the message. The rule name follows in brackets, for example no-implicit-end.
  • Click that name to open the rule's explanation, with a wrong and a right example.
  • The counter at the bottom left of the canvas shows the number of errors and warnings. Click it to hide or show the badges.

Saving and My diagrams

Autosave

The editor keeps your work in the browser one second after each change, and shows the time of the last save next to "Autosave". This autosave has a single slot: clicking New or opening a file replaces its content.

My diagrams

To keep several processes, open My diagrams. Give your work a name and click Save. The list then lets you reopen, rename or delete each entry. Ctrl+S updates the one that is open, and Save as new makes a copy.

This list is stored in this browser, on this device. It is not synced, and it is lost if you clear the site's data or browse in private mode. To keep a process for good, or share it, export it as a .bpmn file.

The Save to choice sets where your work goes: This browser or Server. An entry saved on the server opens from any browser that reaches it, and it is also kept as a .bpmn file (see Your files in the Docker version).

An entry saved in This browser stays on this device. It is not synced, and it is lost if you clear the site's data or browse in private mode. Choose Server to find it elsewhere, or export a .bpmn file to share it.

Open, import, export

Open

  • Open, then .bpmn or .xml file…, opens a file from your disk.
  • Paste XML… opens a diagram copied as code, for example from another tool or an AI answer.
  • From a table… builds a process from a table of steps, without AI (see below).
  • Roles × tasks grid… builds a process in a workshop, one task per row and one role per column (see below).
  • You can also drop a .bpmn file onto the page.
  • Compare with a file… shows the differences between a file from your disk and the open diagram, without changing anything (see below).

The editor reads BPMN 2.0 files from other tools (Camunda, Bizagi, Signavio…). If a file has no layout, the editor computes one on opening. An encrypted file (.bpmn.enc) opens the same way, after its password.

Create from a table (no AI)

Many procedures already exist as a list of steps in Excel. Open, then From a table…, turns them into a diagram: copy the rows in Excel, header included, and paste them into the window, or choose a .csv, .tsv or .xlsx file. The conversion runs in the page, with no AI and nothing sent. A preview counts the steps, links, decisions and lanes before creation, and flags errors (next step not found, duplicate ID).

The Template (.xlsx) button gives a workbook ready to fill in. The editor adds what the diagram lacks: start event, end event, and a merge gateway before a step where several paths join.

Roles × tasks grid (workshop)

In a workshop, listing is faster than drawing. Open, then Roles × tasks grid…, shows a grid: roles in columns, tasks in rows, in order. One click in the cell of the role that performs each task is enough. Enter on the last row adds a task in the same role. A task ending with "?" becomes a decision: Yes leads to the next task, No to an end you can reconnect. Continue in the table… carries the grid over to the From a table window, to add branches, labels or types.

Compare two versions

The comparison window shows two versions side by side, read only: the older one on the left, the open diagram on the right. Open it with Open, then Compare with a file…, or with the Before / after button on the co-pilot's pill.

  • In green, what was added (on the right). In red, what was removed (on the left). In orange, what was changed, on both sides.
  • In blue, on request, what only moved or changed color. Click a chip at the top to show or hide a kind of difference.
  • The list on the right details each difference, for example "Name: Approve → Check the receipts". A click centers both views on the element.
  • Both views scroll and zoom together. Esc closes the window.

Exports asked of the AI

You can ask the AI co-pilot or an MCP agent for a file: "export the diagram as a PDF". It makes the same file as the Export menu (BPMN, SVG, PNG or PDF), under the diagram name or the one you give it. A banner then appears at the bottom of the canvas, with a Download button: the file is downloaded only if you click it. The cross closes the banner, and a new export replaces the previous one.

The file is also saved in the exports folder of the server, whatever the Destination choice, never replacing an existing file.

Encrypted file (AES-256)

A process can reveal an organization, amounts or weaknesses. Export, then Encrypted .bpmn file…, asks twice for a password of at least 8 characters, then downloads a .bpmn.enc file encrypted in your browser: AES-256-GCM, with a key derived from the password by PBKDF2-SHA-256 (600,000 iterations). The password is neither kept nor sent: if it is lost, the file can no longer be opened. Only BPMN-Pilot reopens this file, with Open or by drag and drop. Send the password through another channel than the file.

A reopened encrypted file is not kept in the browser's automatic save: the note "Encrypted file opened, not kept in the browser" says so, and you need to export it again before closing the tab. Only the .bpmn.enc file is encrypted: the other exports (.bpmn, PDF, Word, images) are in clear.

Print

Export, then Print…, opens the browser's print window on the diagram alone, centered with 10 mm margins. The orientation follows its shape: landscape if it is wider than tall, portrait otherwise. Safari leaves that choice to its own print window. A large diagram is shrunk to fit one page, a small one keeps its on-screen size. For a very long process, the PDF or SVG export lets you zoom in.

2. Describe the process

Write it the way you would explain it to a colleague: who does what, in which order, with which decisions. The co-pilot answers in the language of your message. For example:

"Draw the expense claim process. The employee enters the claim, their manager approves or rejects it. Above €500, accounting approves it too. Once approved, it is paid within 5 days. Use one lane per role."

Under each answer, small tags show what the co-pilot did on the canvas: reading, adding shapes, connections, layout… Then ask it for changes ("add a reminder if the manager does not answer within 3 days"), or make them yourself.

  • The input box grows with the text. The button in its corner opens a large editor, to paste long text or open a .txt or .md file. Ctrl+Enter sends.
  • New chat starts over. Your drawing does not change.
  • Stop interrupts an answer in progress.
  • Dictate, under the paperclip, transcribes your voice into the input box, in the interface language. One click starts dictation, another stops it. 3. Start from a file

The co-pilot can also start from a whiteboard photo, a screenshot of an old tool, a procedure in a PDF or a Word document, a list of steps in a spreadsheet, or an export from another tool. Paste the file (Ctrl+V), drop it on the panel, or pick it with the paperclip, then ask the co-pilot to draw it. Up to 5 files per message.

  • Images (PNG, JPEG, GIF, WebP, up to 3.75 MB, reduced to 1568 pixels per side if needed) and PDF (up to 20 MB) go to the model as they are. Claude models read both. With other providers, images depend on the model, and PDFs work with OpenAI and Mistral. An OpenAI-compatible server (Ollama, LiteLLM, vLLM…) gets images, not PDFs. If the chosen model cannot read images, the co-pilot says so instead of a technical error. A PDF over 100 pages goes beyond the limit of most providers: send only the useful pages. Attached files stay in the conversation for the next questions, up to about 15 MB: beyond that, the oldest ones are removed.
  • Office documents (Word, Excel, PowerPoint, and their OpenDocument equivalents: .docx, .xlsx, .pptx, .odt, .ods, .odp) and text files (TXT, Markdown, CSV, JSON, XML, BPMN, HTML, YAML, logs, emails) are read in your browser, and only their text goes with the message: tables become rows, each sheet and each slide keeps its name. Every provider reads them. Only the body text is read: images, charts and SmartArt, headers and footers, comments and speaker notes are left out. If your process is drawn in a SmartArt or a diagram, attach a screenshot of it instead. Dates in a spreadsheet arrive as numbers, and a password-protected document does not open. E-mails (.eml) give their headers (From, To, Date, Subject) and their text; their attachments are only named.

A message holds up to 100,000 characters, attached text included. The Expand the input button, at the top right of the field, opens a larger editor, where Open a file… inserts the text of one of these files so you can trim it before sending.

4. Color and format

The co-pilot can also dress up the diagram: fill, stroke, text color, bold, italic, underline, size and font, on shapes and flows alike. It uses the same settings as the Process panel, and you touch up the result by hand the same way. For example:

"Give each actor its own color, in pale tones. Put the rejection path in red, and the accounting tasks in bold."
  • On a dark fill, it picks white or black text, whichever reads best.
  • The colors it sets are saved in the .bpmn file following the standard, like those set by hand. They join the Used in this diagram styles of the Style group, ready to reuse.
  • Each request is undone in one go with Ctrl+Z, and the "AI" pill counts recolored elements as changed.
  • An MCP agent (Claude Code, Claude Desktop…) can do the same, with the style_elements tool.

See what the co-pilot changed

After each answer, the shapes the co-pilot added get a thin magenta outline and a dot, the shapes it changed a dashed outline. A pill at the top of the canvas sums up, for example "AI: 2 added, 1 changed, 1 removed". Hover over the pill to see the names of the removed shapes.

  • When the co-pilot changes a lot at once, such as a diagram drawn from scratch, no outline is shown: the pill alone sums up. Click it to show the outlines, click again to hide them.
  • Your own edits and automatic layout are never marked. Ctrl+Z updates the marking.
  • Before / after, on the pill, compares the diagram from before the answer with the current one, side by side (see Compare two versions).
  • Undo, on the pill, reverts everything the co-pilot changed since your message in one step, layout included. If you edited the diagram in the meantime, the editor asks you to confirm, since your edits are undone too. Ctrl+Y brings the changes back.
  • The marking is cleared by the pill's cross, by your next message, or when another diagram is opened. It never appears in the file or in exports.

Review and checks

Around each answer, the co-pilot points out what the request leaves open, checks the diagram it produced, fixes on its own what fails, and shows where the result comes from. The details are in Review, checks and traceability. The Review the request and correct automatically box, in Options, turns off the extra requests.

What it costs

The editor is free. AI calls are billed by the provider, to your account, at its rates. The cost depends on the model and the size of the diagram: each message sends it in full. With Ollama, on your own computer, there is nothing to pay. To stay in control, set a spending limit in your provider's console. The review of the request and the automatic correction add requests: turn them off in Options.

For BPMN experts

These features are for testing a model and reporting on it: replaying the process, measuring how instances spread, producing a report, and checking in detail what the AI produces. None of them is needed to draw a diagram.

The Expert button of the toolbar opens a menu: Simulation, Process report (PDF), Process report (Markdown), Process report (Word), then Propose probabilities, AI potential by activity and Co-pilot analysis, greyed out until a model is chosen for the co-pilot: a small help icon says so on hover. Choosing an entry turns expert mode on: the button turns blue, and the Probability (%) field appears in the Process panel. The mode stays on until Leave expert mode, at the bottom of the same menu, and the browser remembers it. This entry is hidden while a simulation runs. Outside this mode, the editor shows none of these tools. The co-pilot checks and the MCP tools are available either way.

Simulation

Expert, then Simulation, switches to simulation mode: a play button appears on each start event. Click it to send a token, and watch it follow the flows. At exclusive gateways, you choose the path. A slider at the bottom of the canvas sets the token speed, from 0.25× to 4×. A log lists the steps taken, so you can check that the process ends in every case. The Expert menu then offers only Stop simulation, and an orange dot on the button shows that a simulation is running. Stopping goes back to editing and keeps expert mode on: the canvas is locked during the simulation, and the branch probabilities are set once it has stopped.

The checkbox marked with a Christmas tree, at the end of the speed box, spins the Leylines gradient around the outline of each step a token enters. It is off by default, and the browser remembers your choice.

Branch probabilities

The Probability (%) field, in the Simulation group of the Process panel, appears in expert mode for a sequence flow leaving an exclusive, inclusive, complex or event-based gateway. It takes a value from 0 to 100 and can be undone like any change.

When a model is chosen for the co-pilot, Propose probabilities, in the Expert menu, asks it for realistic values from the labels, conditions and documentation. Its values are marked like its other changes, and undone in one click. Under the field, "Proposed by the AI co-pilot, to review" stays until you change the value or tick Keep the co-pilot's value. Until then, the process report lists the gateway as to complete.

  • Exclusive, complex or event-based gateway: a single flow is taken. Flows without a value share equally what remains up to 100%, then the whole set is scaled to a total of 100%.
  • Inclusive gateway: each flow is taken according to its own probability, and at least one always is. The join waits for as many tokens as the split sent.
  • Parallel gateway and uncontrolled flows: every flow is taken, and the field does not appear.

The value is saved in the .bpmn file as the bpmnpilot:probability attribute (namespace https://bpmn.leylines.fr/schema/bpmn-pilot/1.0), which other BPMN tools ignore without error. The co-pilot and MCP agents set it with the update_elements tool.

Heatmap

The heatmap shows where the instances of a process go. It colors each element and each sequence flow by the number of tokens that went through it, from pale blue to red. Without reading the model element by element, you see the paths never taken, the activities almost every instance goes through, and the rework loops that run the same activity several times. Use it to validate a model before sharing it, and to find where a process repeats or concentrates before discussing a redesign.

  1. Start the simulation (Expert, then Simulation). The speed box, at the bottom of the canvas, holds two controls: Heatmap, and Run followed by a field that sets the number of tokens, from 1 to 10,000 (100 by default).
  2. Check coverage. Turn on Heatmap, then send a few tokens, picking a different path at each gateway. The map follows every step. Anything left dashed grey was never reached: a forgotten branch, an unreachable end event.
  3. Measure the distribution. Outside the simulation, select each flow leaving an exclusive, inclusive or event-based gateway, and fill in the Probability (%) field of the Simulation group, in the Process panel. Flows without a value share the rest equally. Then start the simulation, enter the number of tokens and click Run (or press Enter in the field): the result is immediate, with no animation.
  4. Read the map. A badge gives the number of passes on each activity and event, with the share of instances ("31 · 31 %"). Above one pass per instance, it gives the average number of executions ("131 · 1.3×"): that is a rework loop. Flow width follows the same count.

The heatmap counts passes: it measures neither durations nor costs. This run follows gateways according to their probabilities, and does not trigger boundary events. The map disappears when the simulation stops, but its counts remain available as long as the diagram does not change: the PDF process report includes it on a page of its own. Probabilities are saved in the .bpmn file, under an attribute of BPMN Pilot that other tools ignore.

Process report

The process report turns the diagram into a document anyone can read without a BPMN tool: a sheet to hand to a team, attach to a quality procedure or present to the process owner. It also works as a modeling review: it lists errors, warnings and missing information, and derives improvement areas by priority.

Expert, then Process report (PDF) or Process report (Markdown). The report is built from the diagram, with no extra input:

  • key figures and the diagram, with each element concerned by a finding outlined in the color of its level;
  • modeling findings, in three levels: Error in red (bpmnlint rule broken, unreachable element, instance that cannot complete), Warning in orange (departure from good practice, frequent rework), To complete in yellow (no documentation, unlabeled conditions, lane with a single activity). Their source is given: bpmnlint, model check or simulation;
  • improvement areas, by priority, with the expected effect;
  • the AI co-pilot's analysis, if one was made (see below);
  • after a simulation, the heatmap and its figures: most traversed activities, passes and observed share of each gateway branch, elements never reached;
  • the six quality checks, computed in the editor, without AI;
  • end events, activities by lane, and the element sequence: type, lane, documentation and outgoing flows with their conditions.

For a complete report, name each gateway with its question and each outgoing flow with its answer, place activities in lanes, and fill in the Documentation field of activities. None of this is required: the report flags what is missing. After a simulation, it adds the heatmap (in PDF), the number of instances per element, the share of each end event and rework.

Co-pilot analysis, in the same menu, asks the co-pilot for a reading of the process: it computes 100 tokens, reads the report, then saves a summary and its points (bottlenecks, rare paths, risks, improvements), each tied to the elements concerned. The analysis is kept in the .bpmn file, where other BPMN tools ignore it: it follows the diagram and is paid for only once. The report presents it as written by the co-pilot, with the model and the date, to be validated by the process owner. If the diagram changes afterwards, the report says so. Ctrl+Z undoes it. Both entries stay greyed out until a model is chosen, and each costs one chat turn. An MCP agent does the same with the set_report_commentary tool.

The report also comes as a Word document, with Process report (Word), to rework and put in your organization's style. It grows with what you fill in: the process identity at the top, the RACI matrix when activities have a RACI, the AI potential, the risks and controls and the compliance matrix when they are filled in.

AI potential by activity (AI adoption)

Where does AI pay off in this process, and with what safeguard? In Expert mode, the Process panel of an activity gains the AI adoption group: AI potential (Automatable, by an AI agent with human review; AI-assisted; Human) and Why, and safeguard. You can fill them by hand, or choose AI potential by activity in the Expert menu: the co-pilot rates each activity from its name, lane, documentation, assignee and systems, saves its rating and reason, then sums up where AI pays off first and the risks to frame. For each automatable or AI-assisted activity, it also adds the risks of handing it to AI and the matching controls, in the Risks and Controls fields, without erasing those already written. The process report lists these ratings in a table, with their reasons.

Risks, controls and requirements (compliance)

To prepare an audit, or to frame a step handed to AI, the Process panel of an activity gains the Risks and compliance group in Expert mode:

  • Risks: what can go wrong at this step, one per line.
  • Controls: what prevents or detects those risks, one per line.
  • Requirements: the regulatory or standard references the step must meet, separated by semicolons (GDPR art. 30; ISO 9001 §8.5; AI Act art. 14).

The process report draws two tables from them. Risks and controls lists each activity concerned, and marks in yellow the one with risks but no control. It also shows in the findings, at the To complete level. Compliance matrix gives, for each requirement cited, the activities that carry it. The procedure sheets show the risks, controls and requirements of each activity. The co-pilot fills them with AI potential by activity, or on request ("list the risks and controls of each activity").

Process identity

Who answers for the process, and which version is this? In Expert mode, when nothing is selected, the Process panel shows the Process identity group: Process owner, Version, Status (Draft, In review, Approved, Retired), Approved on and Scope. The identity opens the process report and the procedure sheets, in PDF, Markdown and Word. The co-pilot and MCP agents can fill it from your documents.

Export for Camunda (8 and 7)

In Expert mode, Export offers BPMN for Camunda 8 and BPMN for Camunda 7. The file opens in Camunda Modeler on the right platform, with what BPMN Pilot can already translate for the engine:

  • the platform and its version are set, and each process is marked executable;
  • gateway conditions are written in the engine's language: FEEL for Camunda 8 (=amount < 3000), JUEL for Camunda 7 (${amount < 3000}). They come from the Condition field, or else from the flow label ("Amount < 3000", or the answer "Yes" to the gateway's question);
  • an activity with an Assigned to value becomes a user task, assigned to that person or role;
  • a rule the engine could not read ("If the customer is loyal") is not written as a condition: it stays in the label, and the final message counts it among the conditions to write in Camunda Modeler, with the unlabelled branches. Forms, connectors and variables are still defined in Camunda.

The open diagram is not changed: only the exported file carries these additions.

Review, checks and traceability

Around each answer, the co-pilot shows what it understood, what the editor checked and where the result comes from.

  • Review of the request. Before drawing a description (200 characters or more, or an attached file), the model lists what is ambiguous or missing: actors, trigger, results, decisions, exceptions and deadlines, loops, documents exchanged, vague wording. Each point has a severity (Blocking, Important, Minor), the question to settle and, when there is one, the passage quoted. The drawing starts right away, with assumptions the model lists at the end of its answer. Answer the questions in your next message to refine the diagram.
  • Check report. After each answer that changed the diagram, the editor checks it itself, without calling the model. The report gives the counts (pools, lanes, activities, gateways, events, flows) and six checks: well-formed XML, conformance to the BPMN 2.0 metamodel (known elements and attributes), references and scopes (a sequence flow stays in its process, a message flow connects two pools), every element drawn (complete DI), reimport by bpmn-js without warnings, no bpmnlint error. Click the report line to unfold the details.
  • Automatic correction. When a check fails, the problems go back to the model, which fixes them on its own, two rounds at most. A correction that does not reduce the number of problems is undone. The report says so, for example "1 correction requested, 1 kept".
  • Traceability. Under each answer: provider, model, duration, date and time, and the source (message length, names of the attached files). Retry from the same source, on the last answer, puts the diagram back as it was before that answer and sends the same request again to the model chosen at that time, for example to compare two models.
  • Destination. A line above the input says where the message goes, to which provider and model: from your browser in the online version, through your server in the Docker version. A provider on your network, such as Ollama, is shown as such. The message, the attached files and the current diagram are sent with each message.

The review and the automatic correction send extra requests to the model: they take time and are billed like the others. The Review the request and correct automatically box, in Options, turns both off. The report, the traceability and the destination line stay.

With an MCP agent

In the Docker version, an MCP agent gets the same checks and the same report:

  • validate_diagram returns the check report: element counts, each check with its problems, the number of errors and warnings, and the bpmnlint issues with element, rule and message;
  • get_process_report returns the process report in Markdown. With simulate, it first computes 100 tokens following the branch probabilities;
  • update_elements also sets the Documentation field and the probability of a branch, marked as proposed by the AI until reviewed;
  • set_report_commentary saves the analysis of the process in the file, for the report;
  • the critique_description prompt lists what is ambiguous or missing in a description, before drawing.

The agent has no automatic correction loop: calling validate_diagram and fixing the problems is up to it. The modeling rules the server gives it ask for this at the end of each drawing.

    Your files in the Docker version

    The server keeps everything in a bpmn-data folder, next to its compose file (or in the folder set by BPMN_DATA_DIR). Open it with your file explorer to get your work back:

    • diagrams: what My diagrams saves on the server, one .bpmn file per diagram, named after it. Renaming an entry renames its file. Leave .index.json in place: this hidden file links the folder to the editor. A .bpmn copied into this folder appears in the list, under its name.
    • exports: the exports made with the Server or Both destination. An export never replaces a file: a second Order process.pdf becomes Order process (2).pdf.

    BPMN-Pilot installs like an application: it then opens in its own window, without the address bar, from the Start menu, the Dock or the home screen.

    Offline

    After a first visit, the editor, this guide and the showcase page open without a connection, installed or not: the browser keeps a copy of the site's files. The animated pictures of this guide are kept once viewed. The AI co-pilot needs a connection to reach its provider: offline, it says so.

    When a new version is published, a banner above the canvas offers to Reload. Nothing reloads on its own, and reloading keeps the diagram in progress.

    On iPhone and iPad, the installed app has its own storage, separate from Safari: the diagrams of My diagrams in Safari do not appear in it. To move a diagram from one to the other, export it as a .bpmn file and open it on the other side.

    Docker version: installation is offered on localhost or over HTTPS. The installed app does not work offline, since the AI co-pilot, the MCP server and saved diagrams go through the server.

    On a phone or tablet

    The editor is designed for a computer screen, a mouse and a keyboard. On a phone, it is mostly for viewing a diagram.

    • What works: opening a .bpmn file or an entry from My diagrams, panning and zooming with your fingers, exporting.
    • What is difficult: placing and connecting shapes, typing labels, using the Process panel and the co-pilot, for lack of room.

    Below 900 pixels wide (or 500 high), a banner above the canvas says so. Close it with its cross: it does not come back in this browser. On a small screen the Process panel also starts hidden. On a tablet, the button on the right of the toolbar opens it. On a phone, the toolbar is wider than the screen and its last buttons are out of reach.

    To model, use a screen at least 1280 pixels wide, or a tablet in landscape with a keyboard and a mouse.

    FAQ

    Do I need an account?

    No. The editor works without an account. Only the AI co-pilot needs an API key from an AI provider.

    No. The editor works without an account. Only the AI co-pilot needs an API key, set on the server or entered in Options.

    Can I use the editor without AI?

    Yes. The whole editor works without an API key: drawing, checks, simulation, saving and exports.

    My diagrams are gone. What happened?

    They are stored in one browser, on one device. So they do not show anywhere else, in private mode, or after the site's data is cleared. Export what you want to keep as .bpmn.

    Those saved in This browser only show there: not in another browser, in private mode, or after the site's data is cleared. Those saved on the Server stay available from any browser. Export what you want to keep elsewhere as .bpmn.

    "Test" fails with OpenAI.

    OpenAI sometimes refuses calls made directly from a web page. Use Anthropic, Mistral, xAI or Ollama on this site, or install the Docker version, which goes through its own server.

    My MCP agent does not draw.

    The agent draws in the last editor tab you used: keep it open. The MCP badge in the toolbar should read "MCP: ready": the tab is linked to the server and waits for an agent. As soon as an agent connects, it shows its name instead, for example "MCP: Claude Code", and hovering it gives its version and the time of its last call. After 15 minutes without activity from the agent, the badge goes back to "MCP: ready", and hovering it still shows the last agent's name. The MCP protocol only sends this name and version: neither the model in use nor the account. Click it to get the address and the settings to paste into the agent again.

    If the agent gets a 401 error "MCP is closed", the editor is served under a name other than localhost without a token, so the server closes MCP access. Generate a token in the Connect an agent window, add it to the server variables (MCP_TOKEN), restart, then paste the new setting into the agent.

    An export to the server, or a save in My diagrams, fails.

    The server cannot write to its data folder: the error message names the folder. The data-init service of the compose file prepares this folder at each start. If the error stays, the folder belongs to another user than the server's (1000 by default, or PUID and PGID): the log docker compose logs mcp says so.

    How do I check what my model can do?

    The command docker compose exec mcp node mcp/check-providers.js tries each model set on the server: reply, tool call, image, PDF. It tells a setting error (key, address, model name) from a limit of the model, and costs a few hundred tokens per model.

    The co-pilot drew something unexpected.

    The pill's Undo button reverts the whole answer at once, Ctrl+Z one change at a time. You can also ask it for the fix in a few words. The more precise the description (roles, decisions, error cases), the better the result. A stronger model also helps with large processes.

    Can I open my files in another BPMN tool?

    Yes. The .bpmn file follows the BPMN 2.0 standard and opens in Camunda Modeler, Bizagi, Signavio and other compatible tools.

    Does it work on a phone or tablet?

    For viewing a diagram, yes. For modeling, not really: the editor is made for a computer screen, a mouse and a keyboard. See On a phone or tablet.
